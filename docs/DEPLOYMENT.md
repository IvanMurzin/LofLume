# GitHub Pages

Сайт: https://ivanmurzin.github.io/LofLume/

## Публикация

- Workflow: `.github/workflows/pages.yml`.
- Публикация из `main` после одного осмысленного завершённого блока изменений.
- Небольшие продуктовые правки накапливаются локально; не пушить каждую отдельно.
- Workflow запускается только при изменении кода, материалов, тестов, сборочных файлов или самого workflow. Документация и AGENTS.md сами по себе публикацию не запускают.
- Ручной запуск: Actions → Check and deploy GitHub Pages → Run workflow, ветка `main`.
- Проверки перед публикацией: типы → тесты → OpenSpec → build. При ошибке новый сайт не публикуется.
- Деплои идут последовательно, без прерывания уже начатой публикации.
- Версии Actions закреплены commit SHA; Node 24, pnpm из packageManager в package.json, зависимости по lockfile.
- Дополнительные пользовательские токены и секреты не нужны: используются разрешения GITHUB_TOKEN на Pages и OIDC.

Первоначальная настройка выполнена владельцем: Settings → Pages → Source → GitHub Actions. Проект публичный; прежние настройки видимости не менялись.

## Проверка префикса локально

```sh
pnpm typecheck
pnpm test
pnpm spec:validate
pnpm build --base /LofLume/
pnpm preview --base /LofLume/ --port 4173 --strictPort
```

Открыть http://127.0.0.1:4173/LofLume/. Сборка и preview должны использовать одинаковый base.

Vite переписывает ссылки в HTML и CSS. Динамические ссылки на фон и музыку проходят через `src/assets.ts` и `import.meta.env.BASE_URL`, включая повторную загрузку картинки после ошибки. Не добавлять динамические абсолютные пути `/audio/...` и `/assets/...` без этого помощника.

Обычный `pnpm dev` продолжает работать в корне http://127.0.0.1:5173/.

## Проверка после публикации

Открыть публичный адрес; проверить картинку и шрифты, запуск радио только кнопкой «Включить», переход треков, часы и короткую сессию с завершением. Публикация текущей промежуточной версии не означает завершение всего MVP: лампа, долгий прогон и итоговая продуктовая приёмка остаются в плане.
