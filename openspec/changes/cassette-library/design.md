# Design

## Context

Принятая комната — React/TypeScript/Vite без сервера, один HTMLAudioElement, локальное хранение громкости/света. Новые кассеты изображены слева рядом с утконосом на v6. См. proposal.md для согласованного сценария.

## Goals / Non-Goals

**Goals:** три локальные кассеты, один активный источник, официальный видимый экран, сохранение существующего стиля и удобства предметов.

**Non-Goals:** универсальный музыкальный SDK, серверный proxy, скрытое YouTube-аудио, обход авторизации/подписок, гарантированное извлечение метаданных всех сервисов.

## Decisions

- Чистый parser нормализует ссылки в разрешённые iframe URL, не принимает произвольный HTML. localStorage хранит версию/три записи; каждую запись повторно валидировать. После reload активной кассеты нет.
- Сохранение и установка разделены. При установке немедленно pause локального радио; старый iframe уничтожается до активации нового. Возврат к радио убирает iframe и открывает обычное управление без play.
- YouTube IFrame API и Spotify iFrame API — загрузка только при установке. API cleanup отменяет поздние callback; никаких глобальных npm-зависимостей. Яндекс — официальный iframe с проверенным собственным postMessage-каналом: display=bandlink-wiki, parentOrigin, READY/STATE/ERROR и PLAY_SOURCE/PAUSE/RESUME/NEXT_TRACK/PREVIOUS_TRACK. Канал найден в официальном плеере v1.86.0; это не стабильный публичный SDK. Проверять origin, source окна и структуру события; при отсутствии READY не показывать фиктивные команды. Подписки и DRM не обходятся.
- Экран в видимом слое сцены справа над радио: 320 px для YouTube/Spotify, 280 px для Яндекса; YouTube viewport 200 px высотой, Яндекс 140 px. Не перекрывать iframe другими панелями. На узком/низком экране экран и открытые инструменты разнести, при недостатке места временно убрать экран вместе с остановкой источника, а не скрывать играющий YouTube.
- Название задаёт пользователь; fallback — сервис и номер. Строка показывает кассету/сервис, без фиктивного автора. Сохранённые URL не загружаются до установки. Внешние плееры могут требовать отдельный play; встроенные ошибки/авторизация остаются у провайдера.
- Оригинальные звуки Web Audio: установка 1.12 s, извлечение .86 s, шорох и защёлка, увеличенная амплитуда .72 × громкость радио, компрессор против пиков. Никаких сторонних аудиоматериалов.
- По правке владельца убрана наша принудительная пауза YouTube при visibilitychange. Инициации PiP нет; у iframe разрешение picture-in-picture запрещено. Не обещать поведение, которое определяет сам сервис, Arc/Chrome или расширения.

## Risks / Trade-offs

- [Сервис блокирует embed/регион/авторизацию] → официальный плеер, оригинальная ссылка и возврат к радио; не считать DOM-тест реальным воспроизведением.
- [Новые форматы Яндекс-ссылок] → проверить реальные iframe и доступные первичные материалы; ошибку встраивания показывать честно.
- [Таймерные панели перекрывают видео] → проверить геометрию на пяти экранах и оставить YouTube не меньше 200×200.
- [Потеря localStorage] → восстановление трёх пустых слотов, работа в памяти без падения.

## Local review update — 25 октября 2026

Владелец потребовал показывать изменения локально и не пушить/деплоить до утверждения. Кассеты — самостоятельные строки; поля выдвигаются справа от выбранной кассеты, при недостатке ширины или пересечении с iframe — под строкой. Внешняя панель не обрезает форму; прокручивается только список. Пустые кассеты коричневые с плюсом, без пунктирных линий и подписи; заполненные — с цветной бумажной этикеткой и кнопками установки/удаления. Изменение открывается повторным кликом по самой кассете. Нижняя геометрия центрирована, кнопки остаются внутри корпуса. У Яндекса три центрированные кнопки без стрелки перехода. В PlayerScreen drag по заголовку использует pointer capture; при drag iframe временно не перехватывает указатель, положение ограничено центральной областью и пересчитывается на resize. Стрелки двигают окно, Home возвращает исходную позицию. Перемещение не пересоздаёт iframe. Контуры заново обведены в координатах v6 1671×941 без старых приблизительных transform.

Последнее уточнение владельца: большой Яндекс-плеер не нужен; требуются компактные предыдущий/пауза/следующий, остальные кнопки — только если реально доступны. Shuffle протокол не предоставляет, фиктивную кнопку не рисовать. Готовый компактный блок проверен в Chrome и в существующей сессии Arc пользователя по его явному поручению, без чтения/экспорта cookies. Ручной Play потребовался из-за ограничений автоматизированного запуска; пользователь подтвердил звук, затем подтверждены реальные смены trackId, pause и resume в Arc.

Футляр 310 px и редактор 220 px; ширина редактора при размещении измеряется по DOM. При закрытии футляра сбрасываются выбранный для редактирования слот, черновик и ошибка. Повторное открытие показывает только список.
