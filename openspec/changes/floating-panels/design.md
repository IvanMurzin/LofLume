# Design

## Context

См. proposal.md. Плеер сейчас ограничен scene-viewport; перезапуск screen-slide-in после data-dragging=false вызывает мигание. TimerPanel рендерится в двух местах в зависимости от кассеты, что может пересоздать карточку.

## Goals / Non-Goals

Общий механизм position:fixed через стабильный React portal в body; все координаты в CSS px viewport. Без DnD-библиотеки и хранения раскладки между reload.

## Decisions

- FloatingPanel владеет drag, resize, z-order и общими header/footer; pointer capture, порог движения, исключение кнопок/полей. Во время жеста iframe не перехватывают указатель.
- Позиция ограничивается по доступности заголовка, а не всей карточки. Resize окна сохраняет доступную ручку. Для заметок отдельные минимальные/максимальные размеры.
- App хранит pin часов/заметок и не закрывает их при открытии других предметов. TimerPanel один стабильный экземпляр; портал не зависит от drag или installed.
- Плеер/редактор сохраняют DOM и соединение. Для перемещения не используется enter-анимация; при отпускании меняется только состояние жеста.
- Первоначальное размещение по возможности избегает других открытых карточек. После этого положение ручное: движение одной карточки не толкает другую.
- Размеры/pin/позиции сохраняются только в текущей сессии. Escape закрывает активную верхнюю карточку, крестик всегда явный.

## Risks / Trade-offs

Iframe/редактор → проверка identity и воспроизведения/undo после перемещения. Узкие экраны → минимумы адаптируются к viewport; ручка остаётся видимой. Дополнительные перекрытия по выбору пользователя → активная карточка поднимается наверх. Контур утконоса уточняется отдельно по текущему artwork без изменения картинки.
